The whole specification as recipes

Every recipe re-expressed in 5 primitives — and the same 5 building the world from an empty game. Generated from tools/research/formulas/data.json.

The one finding

Creation and transformation are already the same format, because the specification has been quietly turning relations into things. deposit and adjacency are kinds. Once a relation is a thing, building the world is change and call with nothing that can refuse — the identical primitives that play the game, and nothing added for world-building at all.

The primitives

There are 5. change carries the guard, so it is the only line that can refuse on a count; set exists only to change a thing that already exists, since a positive change carries its traits.

Primitive What it does Example Why it earns a place
change Add a signed amount to a count, and fail if the result would go below zero change -3 metal in t one operation: creating is a positive amount and spending a negative one
require A read: at least n, and not consumed require 1 adjacency from -> $to the one guard that is not a cost - a read arc, used once
set Assign a trait on a thing that already exists set extractor.ready = no only for changing a thing, since a create carries its traits
attach On any line: what to do when the result would go below zero change -1 labor in t [hard] one question, and hard, soft, clamp and record are its four answers
call Apply another recipe with arguments call found-colony(t) [soft] the hierarchy, and what keeps recipes short without adding expressiveness

The attach column

What happens when a line cannot do what it says. Five values, of which two are in use, one is the absence of a question, one is in the game without a name, and one is a candidate that depends on a decision about a different column.

Value What it means What to know Status
(blank) The count provably cannot go below zero, so no attachment is meaningful. Not a value so much as the absence of a question. Check 4 finds these mechanically: a create whose container has no capacity, a set on a thing that exists. IN USE - create citizen in t
hard The subtraction would go below zero, so the whole action fails and nothing happens. The right default for anything spent. A player is told why, and the state is untouched - so a failure costs nothing but the click. Subtraction as a partial function: undefined, and the caller fails. IN USE - every consume that pays a cost
soft The subtraction would go below zero, so skip this line and carry on. The action still succeeds. A capacity is a count of free space, so a container that will not take another is the same condition as any other underflow. One meaning, not two. IN USE - create garrison in t, and age
clamp Do as much as the state allows. Take 3 where there are 2, and take 2. This is monus - truncated subtraction, the operator that makes the natural numbers a commutative monoid: a - b is 0 when b exceeds a. The standard way to total a subtraction that is otherwise partial. CANDIDATE - and it is now a named operation rather than an invention
record Take what is there, write the shortfall where another recipe can read it, and carry on. `unpaid` is a trait - derived: its upkeep was not met - and `perish` fires on it. So a failed upkeep is neither hard nor soft. This is the value Sean's rule names: the population lost to starvation is an event, never a negative number. IN USE - upkeep, read by perish

Which lines can fail at all

change can, and it is the only line that refuses on a count — that is what fusing the guard into it means. A negative change fails when there is not enough; a positive one fails only where a capacity is declared, which is the same condition seen from the other end, because a capacity is a count of free space. require can, being a read that has to find something. call can, when something inside it fails hard. let can, when a path does not resolve — ark.location.below has no answer for an ark that is not in orbit, and hard is the only sane value there. set effectively cannot, which is why no set in this report carries an attachment.

What is sugar

Removable with linear growth, so by the test each is readability rather than expressiveness — which means they can be added freely.

Written as Means Cost of removing it
create n k change +n k linear - a name for a positive change
consume n k change -n k linear - a name for a negative change
let x = path substitute the path at each use linear - readability only
destroy k change -1 k, where k is an identified thing DELETED as a primitive - it was a change with the count left implicit
threshold(k, at least n) then n destroys change -n k DELETED as two lines - it is one, and 15 of the 16 guards were this
create k then set k.trait change +1 k[trait:value] DELETED - composition is not sequential, so a set on a thing this recipe creates has no referent. Four world-building recipes were this, and 13 lines became 4
limit n k DELETED - a container's capacity, declared once in Capacities both uses were restatements

The last column: every row as one string

The last column of every recipe table restates that row — op, target, amount, attach and the note — as a single string in the notation spec/console.md gives for a command and for a description of state: {name field:value ...}, where a value is a word, a number or another command, a field referring to a thing is named for that thing's kind, and # begins a comment. Two of a territory's four traits have no value anywhere

biome and nature are stored traits of every territory, and no document gives either one a value for any of the twelve. Territory resources has four columns and none of them is a biome; the Biomes table describes what each biome is like and says force of nature is the one column that binds, which binds a territory's nature to a biome it has not been given. The code assigns them — biomes_of, which R-4 vetted — so this is where a thing lives in two authorities at once, and only one of them is a document.

This report asserted otherwise until today. Its world-building data said make-territory(1, grassland, 1), which named a biome for territory 1 and a nature for it, and nothing states either. Removed rather than corrected, because there is no correct value to put there. It was found by trying to draw the table above and having two columns come up empty — which is the argument for drawing it.

metal.density or density.metal: neither

The question only exists because the resource has been moved into the name. density is a variable and metal is a value of a different variable, resource — so once resource is a column there is nothing left to order, and the row above reads {deposit territory:1 resource:metal total-capacity:.. density:..}.

The specification already rules on this, and not by analogy. Nothing in the state is special to a kind. Adding a kind adds no field and no case, and whatever reads the state reads it the same way whatever kind it holds. A territory carrying metal.density, food.density and energy.density gains a field per resource, which is exactly what that forbids. The long form gains a row per resource instead, and rows are free.

The instinct behind the dots is right about presentation and wrong about statement. The release's Territory resources is wide on purpose — one row per territory, a resource per column, 3 x 4 packing two variables into one cell — and it is far easier to read than 13 rows would be. CLAUDE.md already separates these: a table of game data in markdown is a rendering and never a source. Both forms exist above, and the wide one was generated from the long one rather than the other way round.

Resolved 2026-09-09, and it turns on one word

Sean: everything except the game itself has to be in a location. Extractors and stores are attached to the territory and limited by its capacity; a store then has a capacity of its own. A resource and the labor a citizen makes are held by the territory with no limit — labor has to be somewhere, since a citizen makes it and an extractor consumes it.

The release says a territory declares no capacity for a resource, and spec/logistics.md says a kind that declares no capacity contains nothing, and never can. Those two together forbid what the game does. What is meant is no limit, and no capacity is its opposite — one declares an unbounded maximum, the other declares that this sort of thing is never held here. That is X-20, and it is a phrase rather than a rule.

Nothing goes over capacity, and the end of a turn is about disorder rather than overflow

Can go over capacity, with the excess discarded describes resources, and nothing goes over anything. A store holds ten and never refuses, because a resource beyond ten is not in the store — it is held by the territory, which has no limit. What is lost at the turn's end is what the territory holds directly rather than what a container holds.

Sean's reason for it is disorder, and the purpose is that an extractor is useful before anything has been built to store what it makes: work it, spend what it made that turn, and no store was needed. Labor is the pure case - no container ever holds it, so it is always lost, which is why one citizen's labor is one turn's labor and never accumulates.

So this is a lifetime rather than a capacity, and it needs no attach value: nothing failed. The release's phrase for it is a resource that is in nothing, and nothing but the game is in nothing — the same one-phrase fix as above.

Cannot be created there at all is already a rule, and it is not capacity zero

spec/logistics.md: a kind that declares no capacity contains nothing, and never can. That is stronger than a capacity of zero and different in kind — a capacity of zero is a number that could have been another number, and no declaration is a statement about what sort of thing this is. Both appear in the game: territory 6 has a metal extractor capacity of zero, which is a number from Territory resources; an extractor declares no capacity at all, so it holds nothing and never will.

And the spec already carries the reading this report reached from the other side. Total capacity is stored; used and available capacity are derived, available being the total less the used. Available capacity is a counter, and filling a container is subtracting from it — which is the complement construction, in the specification, before this lane suggested it.

What this changed in the model, rather than in the prose

move no longer writes a location. spec/logistics.md says a thing is not located by a trait, and what holds it is what says where it is, so moving is leaving one place and entering another - two changes where there was one assignment. It costs a line and deletes a trait the specification does not have.

Neither check can see the difference, because both aggregate by kind and ignore where a thing is - a loop that moves metal between territories is not a loop that creates metal, so ignoring location is right for them and blind here. That is why X-20 went unnoticed by this lane's own tooling for a day.

Should a kind be a trait?

It already is one. The release's Traits table opens with kind · every thing · one of the kinds · stored, and spec/invariants.md says a thing is a set of traits, and one of them names its kind. So they are not two sorts of thing to be unified; a kind is the value of a trait, and the notation writes it first rather than as kind:citizen because every thing has one.

The question worth asking is the harder one: could it be dropped? If a thing were nothing but its traits, with no discriminator, the traits would have to say which kind it is. They cannot. 7 of the 16 kinds share their trait set with another, so no reading of the traits could tell them apart:

What that settles, and what it does not

Five kinds carry no stored traits whatever. A yard and a unit of metal are the same bag of traits, and only the kind separates them — so kind is not derivable, and dropping it would mean inventing a discriminating trait, which is kind under another name.

It does not settle that kinds are a second sort of thing. They also appear as values: resource takes food, metal or energy, which are kinds, and from and to take places, which are things. spec/console.md already leans on this — a field that refers to a thing is named for that thing's kind. So a kind is doing two jobs: it classifies a thing, and it is a domain that trait values are drawn from. Unify the first job with traits, because it already is one; keep the second, because a value has to come from somewhere.

What unifies, and what must not

The shared object is the description, and the specification says so before this report does. A game's state is things, in places, and how many of each. A thing is a set of traits, and one of them names its kind. That is {kind trait:value ...} — the same object a recipe line targets. So a thing and a recipe line are not two structures to be unified; they are one structure appearing in two roles.

Detecting a glitch, without a cap

Unbounded capacity does not cost you detection

Boundedness for one starting state is EXPSPACE-complete. Boundedness for every starting state is polynomial — a linear program over the incidence matrix. The second is the one an editor needs, because an author is editing recipes and not a saved game. A net is not structurally bounded exactly when there is a non-negative firing vector x, not all zero, with C·x ≥ 0: a set of recipes that, fired in some ratio, ends with more than it began. The vector is the error message — it names which recipes and how many of each.

All of it needs the plain fragment. A zero test on an unbounded quantity makes the language Turing-complete and every line of this section false.

The population ceiling, which no document contains

There used to be three numbers here, and now there is one

Before the fusion this section had to carry two counts and explain the gap. consume was sugar for a guard plus a destroy, so what the machine executed and what a person wrote were different numbers, and the honest figure depended on which you meant. Since the guard and the spend are one line, they are the same number — and the right way to report that is to stop reporting two.

The saving is not the point either. The vocabulary went from four roles that could not name create-if-missing, to six primitives that also build the world from nothing, to 5 that cannot express a zero test. A count of lines cannot see that, which is the whole reason to fix the metric first.

A number that was typed rather than counted, and was wrong

This report said on 2026-09-09 that fusing the guard into the spend took the primitives from six to five. It did not. destroy and threshold became consume, and require split out of the same move — six became six, and the count was a word typed in prose beside a table that disagreed with it. The line saving was real; the primitive saving arrived only with the signed change, a decision later the same day. Every count on this page is now read from the data, this one included, which is why it now says 5.
