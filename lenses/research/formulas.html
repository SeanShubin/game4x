The whole specification as formulas

Every recipe re-expressed in 5 primitives — and the same 5 building the world from an empty game. Generated from tools/research/formulas/data.json.

The one finding

Creation and transformation are already the same format, because the specification has been quietly turning relations into things. deposit and adjacency are kinds. Once a relation is a thing, building the world is change and call with nothing that can refuse — the identical primitives that play the game, and nothing added for world-building at all.

The primitives

Six. set is the one the sketch was missing, and it is what collapses age and refresh from two rows to one each.

Primitive What it does Example Why it earns a place
change Add a signed amount to a count, and fail if the result would go below zero change -3 metal in t one operation: creating is a positive amount and spending a negative one
require A read: at least n, and not consumed require 1 adjacency from -> $to the one guard that is not a cost - a read arc, used once
set Assign a trait on a thing that already exists set extractor.ready = no only for changing a thing, since a create carries its traits
attach On any line: what to do when the result would go below zero change -1 labor in t [hard] one question, and hard, soft, clamp and record are its four answers
call Apply another formula with arguments call found-colony(t) [soft] the hierarchy, and what keeps formulas short without adding expressiveness

The attach column

What happens when a line cannot do what it says. Five values, of which two are in use, one is the absence of a question, one is in the game without a name, and one is a candidate that depends on a decision about a different column.

Value What it means What to know Status
(blank) The count provably cannot go below zero, so no attachment is meaningful. Not a value so much as the absence of a question. Check 4 finds these mechanically: a create whose container has no capacity, a set on a thing that exists. IN USE - create citizen in t
hard The subtraction would go below zero, so the whole action fails and nothing happens. The right default for anything spent. A player is told why, and the state is untouched - so a failure costs nothing but the click. Subtraction as a partial function: undefined, and the caller fails. IN USE - every consume that pays a cost
soft The subtraction would go below zero, so skip this line and carry on. The action still succeeds. A capacity is a count of free space, so a container that will not take another is the same condition as any other underflow. One meaning, not two. IN USE - create garrison in t, and age
clamp Do as much as the state allows. Take 3 where there are 2, and take 2. This is monus - truncated subtraction, the operator that makes the natural numbers a commutative monoid: a - b is 0 when b exceeds a. The standard way to total a subtraction that is otherwise partial. CANDIDATE - and it is now a named operation rather than an invention
record Take what is there, write the shortfall where another formula can read it, and carry on. `unpaid` is a trait - derived: its upkeep was not met - and `perish` fires on it. So a failed upkeep is neither hard nor soft. This is the value Sean's rule names: the population lost to starvation is an event, never a negative number. IN USE - upkeep, read by perish

Which lines can fail at all

change can, and it is the only line that refuses on a count — that is what fusing the guard into it means. A negative change fails when there is not enough; a positive one fails only where a capacity is declared, which is the same condition seen from the other end, because a capacity is a count of free space. require can, being a read that has to find something. call can, when something inside it fails hard. let can, when a path does not resolve — ark.location.below has no answer for an ark that is not in orbit, and hard is the only sane value there. set effectively cannot, which is why no set in this report carries an attachment.

The one formula that needs it today

record is the one worth looking at, because it is already there

unpaid is a trait in the specification — derived: its upkeep was not met — and perish fires on it. So when upkeep cannot take its food, the failure neither stops the turn nor vanishes: it is written down, and another formula reads it next. That is a third behaviour on failure, in the game today, which a two-valued column cannot express.

It may not want to be an attach value. The alternative is that failure is state — every line's outcome is recorded, and unpaid is just one query over it. That is a larger idea and a cleaner one, and it is the sort of thing worth deciding before the column sets rather than after.

Every row as one string

The last column of every formula table below restates that row — op, target, amount, attach and the note — as a single string in the notation spec/console.md gives for a command and for a description of state. All 56 lines are encoded, none by hand.

What the encoding assumes, and why it is worth reading

The notation says a command is {name field:value ...}, that a value is a word, a number or another command, that a field referring to a thing is named for that thing's kind, and that # begins a comment. Where a line needed something that notation does not define, the encoder records it rather than inventing quietly — so this list is the report's real output, and it is generated from the encoding rather than written beside it.

Detecting a glitch, without a cap

Unbounded capacity does not cost you detection

Boundedness for one starting state is EXPSPACE-complete. Boundedness for every starting state is polynomial — a linear program over the incidence matrix. The second is the one an editor needs, because an author is editing formulas and not a saved game. A net is not structurally bounded exactly when there is a non-negative firing vector x, not all zero, with C·x ≥ 0: a set of formulas that, fired in some ratio, ends with more than it began. The vector is the error message — it names which formulas and how many of each.

All of it needs the plain fragment. A zero test on an unbounded quantity makes the language Turing-complete and every line of this section false.

Check What it asks Cost and character What it reports Where it fits
1. Declared conservation P-invariant: is there a weighting under which this resource's net change is zero across every formula? Polynomial. EXACT - it cannot cry wolf. Names the formula that breaks it. Targets exactly "I accidentally made metal from nothing". The spec already declares which resources are conserved; nothing checks it.
2. Structural unboundedness T-increasing: is there a non-negative firing vector x, not all zero, with C.x >= 0? Polynomial by linear programming. CONSERVATIVE - it ignores guards, so it can flag a loop the guards prevent, and cannot miss one. The firing vector IS the witness: which formulas, in what ratio. Catches loops nobody declared. Must be reported as a diff against intended loops, because the citizen economy is genuinely a T-increasing.
3. A large generic cap at runtime Stop and report if any count passes a big number. Cheap. Detects after the fact, in one playthrough, at whatever numbers that run happened to hit. Says a number got large. Says nothing about which formulas did it. Keep as a backstop against bugs in checks 1 and 2. Never as the mechanism - a cap that fires tells you nothing about why.

Why the broad check must be a diff

The intended economy is itself an infinite loop. Food feeds citizens, citizens make labor, labor works extractors, extractors make food. That is a T-increasing and a structural check will flag it — correctly. So check 2 cannot ask is anything unbounded; it asks is anything unbounded that was not there before. Check 1 has no such problem, because the author names the resource that must not grow and food is simply not on the list.

Why it stays out of the table

Reproduction caps the per-capita rate at 1 — a parent per child. Food caps it at d−1. So the realised rate is min(d−1, 1). Every density in the release is an integer, so the food-limited middle case never occurs: a territory either doubles or is frozen.

Density does two things, and speed is not one of them

Territory 3 is 6 x 2 and territory 8 is 6 x 6. They grow at exactly the same rate — both double every turn — and differ only in where they stop: ceiling 12 against 36. Above density 2, extra density buys ceiling and surplus, never speed. A reader who takes 6 x 6 as six times faster would be wrong, and the release does not say otherwise anywhere.

Which raises a question about the surplus, and about food stores

Territory 8 produces 5n surplus food and grow can use only n of it. The other 4n has nowhere to go. Food is made with keeps 1, and the turn runs upkeep, grow, perish, age, spoil — so food made this turn is aged to 0 and spoiled at the same turn end, whether it sits in a store or in nothing.

If that reading is right, a food store buys nothing, because stored and unstored food die at the same moment. It may be that storing is meant to reset keeps and nothing says so. Raised rather than filed as a defect — and it is a curious postscript to dropping the two stores from found-colony, one of which was a food store.

The population ceiling, which no document contains

Per citizen per turn: upkeep eats 1 food, create labor yields 1 labor, and work turns 1 labor into d food. So with n citizens and c food extractors, the surplus is n(d−1) while n ≤ c, and c·d − n after that. It reaches zero at n = c·d — so a territory's population ceiling is its food capacity times its density, which is the Food column read as a product.

Every note is explained by that one number, and one of them says so out loud

Territories 2 and 3 are 2 x 6 and 6 x 2 — different shapes, ceiling 12 both — and the release's own note on territory 3 reads many thin food extractors, same food total. Territory 9 has a ceiling of 6 against metal capacity 6: rich metal, too few hands to work it. Territory 12 has a ceiling of 4 against 8 metal extractors: rich extractors, almost no workers. The notes were written from a quantity that was never written down.

And territory 5 is sharper than its note. At density 1 a citizen eats exactly what it produces, so the surplus is n(1−1) = 0 at any size: it is not merely low-ceilinged, it cannot grow at all and is frozen at whatever founds it. The note says Food density 1; the consequence is that the ceiling of 3 is unreachable.

One thing the chain does not explain, and it is worth knowing

grow produces the lesser of the surplus food and the citizens here, so growth caps at doubling per turn however dense the food is. Density above 2 does not make a colony grow faster — it makes surplus for something else. So the ceiling and the growth rate are set by different halves of the same column, and a reader who takes 6 x 6 as six times faster would be wrong.

The citizen question mark is not a decision

A territory never refuses a citizen — they are held down by food through upkeep, which is not a capacity. So hard and soft are the same line. The options are below, and the only one that behaves differently is a second reading of the word soft rather than a second value of it.

Option What it does What it costs Applies to
Leave it unattached The line cannot fail, so it always runs. Deploying onto an inhabited territory adds 2 more citizens. Recommended. A citizen is a quantity, and 2 is an increment. citizen
hard Fail the action if the citizen cannot be created. Identical behaviour today, and forever unless a population cap is added. A word that decides nothing. citizen
soft, reading soft as *the container is full* Skip the line when the container will not hold another. Identical behaviour today, for the same reason: a territory has no citizen capacity. citizen
soft, reading soft as *one is already there* Skip when the territory already has any citizen. Observably different, and it turns 2 from an increment into a target. Almost certainly not wanted for a quantity - but this is the line where the two readings of soft come apart. citizen
Decide at the call instead call found-colony(t) [soft], guarded on the garrison. Answers all three question marks at once: deploying onto a founded colony spends the ark and does nothing else. all three

Withdrawn: what does soft test was a false choice

An earlier version of this report asked whether soft means the container is full or one is already there. There is exactly one condition under which a create can fail — the container will not take another — so there is one meaning and not two. The second reading was this lane's invention with no case behind it, and Sean was right not to understand the question.

The real distinction it was standing in front of is about create, not about soft. create X [soft] means add one if there is room, which is not the same as ensure one exists. Those coincide wherever capacity is 1 — every case here except the extractors. Territory 1 has food capacity 3, so deploying twice would add a second food extractor. If that is wrong, the fix is at the call — do not found a colony that is already founded — and not a second kind of create.

Parameter domains — what a formula may be instantiated over

A parameter is not free. Its domain is a condition on the kind, not a list, and grounding resolves it — so an instance that does not satisfy the condition never exists, and in a selection interface the player never sees it.

Formula Parameter Domain Today Why
build store $resource a resource whose things do not expire metal, energy food is excluded because it is made with keeps 1 and dies at the turn end it was made, so a food store cannot hold anything across a turn
build extractor $resource a resource this territory has a deposit for per territory territory 6 has no metal deposit, so build extractor[metal] does not exist there - check 5
work extractor.resource the resource the selected extractor was built for not a choice determined by the selection, so it grounds to one instance rather than a domain

Food stores, and why the rule is derived rather than named

Sean, 2026-09-09: a food store buys nothing, so it is out. The tempting fix is to write no food stores. The better one is a store may be built for a resource whose things do not expire, which today admits metal and energy and excludes food, because food is made with keeps 1 and dies at the turn end it was made.

Preservation technology raises food's keeps, and food stores become available with no change to the rule. That is the difference between a condition and a list: one of them already knows about a feature that does not exist yet.

Two reasons agreeing is not two pieces of evidence

found-colony has no stores. That was decided for conservation — garrison plus two extractors is 3, exactly an ark's Binding — and the food store also turns out to buy nothing, so it would have gone anyway. The metal store does buy something and still stays out: a new colony gets the minimum that works and builds its own. Worth separating, because a decision that looks doubly supported is easy to stop examining.

What the re-encoding cost and saved

Computed from the data rather than asserted. 58 rows became 48 lines — down 10.

There used to be three numbers here, and now there is one

Before the fusion this section had to carry two counts and explain the gap. consume was sugar for a guard plus a destroy, so what the machine executed and what a person wrote were different numbers, and the honest figure depended on which you meant. Since the guard and the spend are one line, they are the same number — and the right way to report that is to stop reporting two.

The saving is not the point either. The vocabulary went from four roles that could not name create-if-missing, to six primitives that also build the world from nothing, to 5 that cannot express a zero test. A count of lines cannot see that, which is the whole reason to fix the metric first.
