## What was measured and is sound

**No algorithmic crate can reach a platform concern.** `sphere-tessellation` and `planet-model` take
nothing; `graph-coloring` takes only `sphere-tessellation`; `planet-terrain` takes those two. The
isolation `docs/process.md` asks for holds at the manifest, which is where it can be enforced rather
than remembered.

**The engine appears in almost no public surface.** Counting public items that name a Bevy type, in
the four library crates that link it:

| Crate         | Public items naming an engine type                       |
| ------------- | -------------------------------------------------------- |
| `planet-bevy` | 0 of 14                                                  |
| `game-globe`  | 0 of 1                                                   |
| `planet-ecs`  | 1 of 13 - a system signature, which must have that shape |
| `planet-flat` | 2 of 13                                                  |

**The game/engine coupling is in exactly one crate.** `planet-bevy/src/globe.rs` names `game_front`
**zero** times; `game-globe/src/lib.rs` names it five. That coupling was
[the sixth finding of the first report](2026-08-28-crate-boundaries-and-duplication.md#6), when it
was spread across a crate the prototypes had to link. It is now 195 lines with a name that says what
it is.

**The split crates delegate rather than duplicate.** `readable_on` and `summary` are defined in both
`planet-bevy` and `planet-presentation`, which is what a name collision looks like when a move
leaves a copy behind. Reading the bodies: both call `planet_presentation` and convert the result to
an engine type. The logic lives once.

**Both composition roots name only what they use**, and `docs/architecture.md`'s crate table matches
the workspace exactly - nineteen members, no row without a crate, no crate without a row - held by
`tools/outbox/tests/architecture.rs`, which asserts both directions and carries a floor so it cannot
pass vacuously.

## One gap left open deliberately

`P-245` - *a document that restates another links to it instead of listing it* - is enforced by
nothing. Two documents were made stale by it on the day it was promoted, and both were repaired by
hand after being pointed out.

**Not filed**, because the rule's own remedy is *stop copying* rather than *check the copies*, and
detecting that one document restates another is a semantic question rather than a countable one.
`docs/process.md` asks for rules enforced by code **where possible**, and this may be a case where
it is not. Recorded so that the next person to wonder does not have to re-derive the reason.

## What this sweep cost in false starts

Four patterns of this lens's own were wrong before anything held, and all four were the same shape -
a query answering a narrower or wider question than the one being asked.

- An engine-type scan counted `Resource`, `Entity`, `Vec3` and `Color` as Bevy types. They are
  domain names here, so it reported leakage in crates with no engine at all. Restricting it to
  crates that *can* name Bevy is what made the numbers mean anything.
- A shell pipeline reported zeros for every crate because `bc` did not exist and the `grep -E`
  never matched.
- A glob over `crates/*/tests/` missed `tools/outbox/tests/architecture.rs` and nearly produced a
  finding that `S-2` had been closed without its guard. **The guard exists and passes.**
- The name-collision detector flagged `readable_on` and `summary` as duplication. Reading the
  bodies cleared them.

The last two are the useful ones: both were signals that survived to the point of nearly being
written down, and both were killed by opening the file rather than by being more careful.
