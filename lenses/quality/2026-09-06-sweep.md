## 1. The data file moved away from `P-284` today, and the obvious fix is the wrong one

**Where.** `scenario/expected/play.4x:163` - `{unit id:1 kind:ark in-kind:orbit in-id:2 fuel:1
ready:yes}`, written by `S-55` in `f3dcc1e`.

**What.** `P-284`: *every word in a data file is a kind, a trait, or one of a trait's values.*
Re-derived by classifying all **50** distinct words in the file against the release's own tables,
rather than by arithmetic on the earlier figure: **the count of forbidden words is 19**, against
**17** this morning. `play` became legal when `P-309`/`P-310` named `phase`'s values; `in-kind` and
`in-id` arrived and are neither traits nor trait values.

    amount, built, capacity, citizens, count, game, in-id, in-kind, in-play, labor-spent,
    left, made, spent, structure, territories, territory-resource, turn, units, yards

**Why it is more than two more words on a list.** **Declaring them as traits is the fix that
suggests itself and it is wrong.** `spec/console.md` says *where a thing is, is where it appears;
nothing states its container* - so `in-kind` and `in-id` are not words the data file is missing a
declaration for, they are words the data file must **stop having** when `S-47` lands the map form.
A `Traits` row for either would be a rule the specification does not want, promoted to silence a
check.

**And it is `C-37`'s arrow, observed moving.** `C-37` says the data file inherits its vocabulary
from `dump::tables` because `expected::rows` iterates it. `P-311` gave the **dump** a containment
form; the data file took it the same afternoon, without anyone deciding it should. That is the
mechanism working exactly as `C-37` predicted, on the first occasion after it was filed.

**No fault in the code lane's change.** `P-311` is promoted, `S-54` names `in-kind`/`in-id` as the
answer, and they used the promoted form rather than inventing one. The defect is that a
presentation's vocabulary reaches a data file with nothing in between.

**Whether.** Worth a decision before `S-47` is built, because `S-47` is where it is either removed
or entrenched. Filed as `Q-64`.

## 2. `S-55`, and the three things the code lane asked to be challenged

All three hold. Recorded because *checked and sound* is worth as much as a finding when somebody
asked.

**The constraint has a check that would have failed before it, and it is the only one.** Poisoned in
a clone by relaxing `land`'s predicate back to `matches!(unit.location, Location::Orbit(_))` - the
pre-`S-55` behaviour. `an_ark_lands_only_on_the_territory_its_orbit_is_above` fails and **52 other
tests pass**. So the rule was genuinely unguarded and is now genuinely guarded.

**It matches the specification, read rather than taken from the commit message.** `spec/orbit.md`:
*nothing orbits a planet without being above a particular territory*, *an orbit is next to the
territory below it*, and *launching, landing and crossing from one orbit to another are moves*. The
model now carries `Location::Orbit(TerritoryId)` and constrains landing to the ground beneath.

**The test is stronger than it needed to be, and this may be luck.** `designed()` builds `ring(3)`,
so **territory 3 is adjacent to territory 1**. Refusing a landing on 3 therefore distinguishes
*beneath* from *adjacent*, which a distant territory would not have done. The `TerritoryId(7)` they
were unsure about would have been out of range for a three-territory helper and would have tested a
different rejection.

**The two surviving `TerritoryId(7)`s are correct**, and are not a half-applied edit:
`rejection.rs:280` and `:310` construct a `Rejection` directly and assert its rendered string, so no
territory has to exist.

**The expected row is right, derived from the commands rather than from the program.**
`world.4x:16 add ark orbit 1`; `play.4x:19 land ark 1`; `:164 produce ark 1`; `:170 move ark 2`;
`:182 launch ark`. The surviving Ark launches from 2, so `in-id:2`.

**And the rejection variant earns its existence.** The test pins `NotAboveThatTerritory { above,
asked }` by field, and separately pins that an empty orbit gives `NoUnitAvailable` - *above somewhere
else* and *nothing there* are different facts, and a green test would not have told them apart.

## 3. Noted, and deliberately not

real the first time a kind's table is empty. Recorded so a later report does not present it as new.
